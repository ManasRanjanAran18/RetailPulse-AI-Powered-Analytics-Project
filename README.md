# 📈 RetailPulse - AI-Powered Customer Analytics & Demand Forecasting Platform

[![CI](https://github.com/YOUR_GITHUB_USERNAME/retailpulse-analytics/actions/workflows/ci.yml/badge.svg)](https://github.com/YOUR_GITHUB_USERNAME/retailpulse-analytics/actions/workflows/ci.yml)

RetailPulse is an end-to-end **Data Science & Analytics** project that helps retail businesses make smarter
decisions with machine learning and predictive analytics. It analyses **sales, customer and inventory data** to deliver
**demand forecasting, customer segmentation, churn prediction and inventory optimisation**, with the goal of
reducing stock-outs, improving retention and increasing revenue.

**Tech stack:** Python · Scikit-learn · Prophet · LSTM (TensorFlow/Keras) · Streamlit · MLflow · Optuna · Docker · Kubernetes · GitHub Actions

## ✨ Key features

| Capability | What it does | Where |
|---|---|---|
| **AI demand forecasting** | Hybrid ensemble of Gradient Boosting + Prophet + LSTM, weighted by backtest error, with 90% intervals | `src/forecasting/` |
| **Customer behaviour analysis** | RFM features + K-Means → 4 actionable personas (Champions, Loyal, At Risk, Hibernating) | `src/segmentation/` |
| **Churn prediction** | Gradient-boosted classifier, leakage-safe features, risk bands, revenue-at-risk | `src/churn/` |
| **Inventory optimisation** | Safety stock, reorder point, EOQ, stock status, purchase-order suggestions | `src/inventory/` |
| **Automated ETL** | Validation, de-duplication, return/price handling, analytics tables | `src/ingestion/` |
| **Interactive dashboards** | 6-page Streamlit app with filters, what-if service-level slider, CSV exports | `dashboard/app.py` |
| **MLOps** | MLflow tracking + model registry, drift detection (PSI/KS), CI/CD, Docker, Kubernetes | `mlflow/`, `src/monitoring/`, `.github/`, `docker/`, `k8s/` |

## 📊 Results on the bundled demo dataset

| Task | Result |
|---|---|
| Demand forecast (60-day holdout, incl. Nov-Dec peak) | Hybrid ensemble **MAE 13.1 units/day (WAPE 10.2%)** - better than Prophet (14.0), GBM (15.6) or LSTM (17.6) alone |
| Churn prediction | **ROC-AUC 0.90**, precision 0.81, recall 0.64 (26% base churn rate) |
| Segmentation | 4 segments, silhouette 0.38; *Champions* = 30% of customers but ~62% of revenue |
| Inventory plan (40 SKUs) | 1 critical, 3 reorder-now, 7 overstock, 29 healthy |
| Data quality (ETL) | 163 duplicates removed, 109 missing prices imputed, 218 returns/invalid lines excluded |

> The dataset is **synthetic** (generated by `src/ingestion/synthetic.py`) so the project runs anywhere. Swap in real CSVs - see *Using your own data*.

## 🚀 Quick start

```bash
python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt                        # dashboard + core ML
streamlit run dashboard/app.py                         # http://localhost:8501
```

Everything needed to view the dashboard is already committed. To **retrain**:

```bash
pip install -r requirements-full.txt                   # Prophet, TensorFlow, MLflow, Optuna ...
python scripts/run_pipeline.py --mlflow                # ≈30-60 s, full hybrid ensemble
python scripts/run_pipeline.py --light                 # ≈3 s, GBM only (no heavy deps)
./rerun_all.sh                                         # tests + pipeline + re-execute all notebooks
python -m pytest tests -q                              # unit tests
mlflow ui --backend-store-uri sqlite:///mlflow/mlflow.db   # browse experiments
```

## 🧪 Using your own data

Drop CSVs with these columns in `data/raw/`, then run `python scripts/run_pipeline.py`:

| File | Required columns |
|---|---|
| `transactions.csv` | `order_id, order_date, customer_id, product_id, category, quantity, unit_price, store` |
| `customers.csv` | `customer_id, signup_date, region, loyalty_tier (Bronze/Silver/Gold), age` |
| `products.csv` | `product_id, product_name, category, unit_price, unit_cost` |
| `inventory.csv` | `product_id, current_stock, lead_time_days, unit_cost, holding_cost_rate, order_cost, supplier` |

Regions are defined in `src/config.py` (`REGIONS`) - adjust to match your data.

## 🧠 Design notes

- **No label leakage in churn:** features use data strictly before a cutoff; the label looks at the following 90 days.
- **Stable GBM forecasts:** lags are expressed relative to the trailing 28-day level, which removed a +22 units/day bias seen with raw lags.
- **Honest evaluation:** the holdout deliberately contains the seasonal peak; tuning (Optuna) uses an inner validation split.
- **Lean deployment:** the runtime image needs only 7 packages (~280 MB RAM); heavy training libraries are optional and lazily imported.
- **Graceful degradation:** if Prophet/TensorFlow are missing the pipeline skips those models and reweights the ensemble automatically.
